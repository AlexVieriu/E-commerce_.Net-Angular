S07.01.Easy. What does <code>??=</code> do in C#? Give an example.	<p><code>??=</code> is the null-coalescing assignment operator. Assigns the right side only if the left side is null. Example: <code>name ??= "default";</code> — if <code>name</code> is null, assigns <code>"default"</code>; otherwise keeps current value. Equivalent to: <code>if (name == null) name = "default";</code></p>
S07.02.Easy. What does <code>?.</code> do? What does <code>!</code> (null-forgiving operator) do? When is <code>!</code> dangerous?	<p><code>?.</code> short-circuits to null if the left side is null: <code>order?.Customer?.Name</code> returns null instead of throwing. <code>!</code> tells the compiler "trust me, this isn't null" — suppresses nullable warning. Dangerous because: if you're wrong, you get a <code>NullReferenceException</code> at runtime. <code>!</code> hides bugs — use only when you're genuinely certain.</p>
S07.03.Easy. What is the difference between <code>string?</code> and <code>string</code> in a nullable-enabled context?	<p><code>string</code> = non-nullable reference type — compiler warns if you assign null. <code>string?</code> = nullable — explicitly allows null. In nullable context (<code><Nullable>enable</Nullable></code>), the compiler tracks null flow and warns about potential <code>NullReferenceException</code>. It's a compile-time check only — no runtime difference.</p>
S07.04.Easy. What does <code>init</code> accessor do on a property? How is it different from <code>set</code>?	<p><code>init</code> allows the property to be set only during object initialization (constructor or object initializer). After construction, it's read-only. <code>set</code> allows modification at any time. <code>init</code> enables immutable objects with convenient initialization: <code>new Order { Id = 1, Status = "New" }</code> — but <code>order.Status = "Done"</code> later won't compile.</p>
S07.05.Easy. What does <code>required</code> keyword do on a property in C# 11?	<p><code>required</code> forces the caller to set the property during initialization — compiler error if omitted. <code>public required string Name { get; init; }</code> means <code>new Person { Name = "Alex" }</code> is required — <code>new Person()</code> won't compile. Replaces constructor parameters for mandatory properties, especially useful with <code>init</code> and records.</p>
S07.06.Easy. What does <code>inject()</code> function do in Angular? How is it different from constructor injection?	<p><code>inject()</code> is a function-based alternative to constructor injection (Angular 14+). Works in constructors, field initializers, and injection context (route guards, interceptors). Advantages: works in standalone functions (functional guards/interceptors), enables composition (utility functions that inject services), reduces constructor boilerplate. Limitation: must be called in an injection context.</p>
S07.07.Easy. What does <code>takeUntilDestroyed()</code> do? Why is it important for preventing memory leaks?	<p><code>takeUntilDestroyed()</code> (Angular 16+) automatically completes an observable when the component/directive is destroyed. Prevents memory leaks from long-lived subscriptions (WebSockets, intervals, Subjects). Usage: <code>this.data$.pipe(takeUntilDestroyed()).subscribe(...)</code>. Must be called in injection context (constructor or field initializer). Replaces the manual <code>ngOnDestroy</code> + <code>Subject</code> pattern.</p>
S07.08.Easy. Write a one-liner: convert <code>string[] names</code> to a comma-separated string of names longer than 3 characters, sorted alphabetically.	<pre><code>string result = string.Join(", ", names.Where(n =&gt; n.Length &gt; 3).OrderBy(n =&gt; n));</code></pre><p>Filter with <code>Where</code>, sort with <code>OrderBy</code>, join with <code>string.Join</code>. <code>OrderBy</code> is alphabetical by default for strings.</p>
