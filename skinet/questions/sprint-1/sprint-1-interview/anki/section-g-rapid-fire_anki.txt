S07.01.Easy. What does <code>??=</code> do in C#? Give an example.	<p><code>??=</code> is the <b>null-coalescing assignment</b> operator — assigns the right side only if the left side is <code>null</code>.</p><pre><code>name ??= "default"; // Equivalent to: if (name == null) name = "default";</code></pre><p>Useful for lazy initialization of nullable fields.</p>
S07.02.Easy. What does <code>?.</code> do? What does <code>!</code> (null-forgiving operator) do? When is <code>!</code> dangerous?	<ul><li><b><code>?.</code></b> (null-conditional) — short-circuits to <code>null</code> if the left side is <code>null</code>:</li></ul><pre><code>  string? city = order?.Customer?.Address?.City; // null instead of NullReferenceException</code></pre><ul><li><b><code>!</code></b> (null-forgiving) — tells the compiler "trust me, this isn't null." Suppresses the nullable warning but provides <b>no runtime safety</b>.</li></ul><p><b>When <code>!</code> is dangerous:</b> if you're wrong about null, you get a <code>NullReferenceException</code> at runtime with no compile-time warning. Use only when you are genuinely certain.</p>
S07.03.Easy. What is the difference between <code>string?</code> and <code>string</code> in a nullable-enabled context?	<ul><li><b><code>string</code></b> — non-nullable; compiler warns if you assign <code>null</code> or pass it where null may occur.</li><li><b><code>string?</code></b> — explicitly allows <code>null</code>; compiler tracks null flow and warns before dereferencing.</li></ul><p>Requires <code><Nullable>enable</Nullable></code> in <code>.csproj</code>. <b>Compile-time analysis only</b> — no runtime difference between <code>string</code> and <code>string?</code>.</p>
S07.04.Easy. What does <code>init</code> accessor do on a property? How is it different from <code>set</code>?	<p><code>init</code> allows a property to be set <b>only during object initialization</b> (constructor or object initializer). After construction it becomes read-only. <code>set</code> allows modification at any time.</p><pre><code>public class Order {     public int Id { get; init; }     public string Status { get; init; } }  var order = new Order { Id = 1, Status = "New" }; // ✅ order.Status = "Done"; // ❌ CS8852: init-only property</code></pre>
S07.05.Easy. What does <code>required</code> keyword do on a property in C# 11?	<p><code>required</code> forces the caller to set the property during object initialization — <b>compiler error if omitted</b>.</p><pre><code>public class Person {     public required string Name { get; init; } }  new Person { Name = "Alex" }; // ✅ new Person();                 // ❌ CS9035: required member 'Name' must be set</code></pre><p>Replaces constructor parameters for mandatory properties — especially useful with <code>record</code> and <code>init</code>.</p>
S07.06.Easy. What does <code>inject()</code> function do in Angular? How is it different from constructor injection?	<p><code>inject()</code> is a functional alternative to constructor injection (Angular 14+).</p><pre><code>// Constructor injection constructor(private router: Router) {}  // inject() — works anywhere in injection context readonly router = inject(Router);</code></pre><p><b>Advantages:</b></p><ul><li>Works in field initializers, functional guards, and interceptors — not just constructors.</li><li>Enables composable utility functions that inject services internally.</li><li>Reduces constructor boilerplate with many dependencies.</li></ul><p><b>Limitation:</b> must be called during construction (in an injection context).</p>
S07.07.Easy. What does <code>takeUntilDestroyed()</code> do? Why is it important for preventing memory leaks?	<p><code>takeUntilDestroyed()</code> (Angular 16+) automatically completes a subscription when the component/directive is destroyed.</p><pre><code>// Before — manual cleanup private destroy$ = new Subject&lt;void&gt;(); ngOnInit() { this.data$.pipe(takeUntil(this.destroy$)).subscribe(...); } ngOnDestroy() { this.destroy$.next(); this.destroy$.complete(); }  // After — zero boilerplate constructor() {     this.data$.pipe(takeUntilDestroyed()).subscribe(...); }</code></pre><p><b>Why it prevents memory leaks:</b> without cleanup, long-lived observables (WebSockets, intervals, <code>Subject</code>) keep running after the component is destroyed — holding references in memory and causing errors on destroyed UI. Must be called in an injection context.</p>
S07.08.Easy. Write a one-liner: convert <code>string[] names</code> to a comma-separated string of names longer than 3 characters, sorted alphabetically.	<pre><code>string result = string.Join(", ", names.Where(n =&gt; n.Length &gt; 3).OrderBy(n =&gt; n));</code></pre><p>Filter with <code>Where</code>, sort with <code>OrderBy</code>, join with <code>string.Join</code>. <code>OrderBy</code> is alphabetical by default for strings.</p>
