S01.01.Easy. What is the difference between <code>readonly</code> and <code>const</code> in C#? When would you use each?	<ul><li><b><code>const</code></b> — compile-time, implicitly static, must be assigned at declaration, only works for primitives/strings.</li><li><b><code>readonly</code></b> — runtime, can be set in the constructor, works for any type.</li></ul><p>Use <code>const</code> for true constants (e.g. <code>Math.PI</code>), <code>readonly</code> for values set at construction (config, injected dependencies).</p>
S01.02.Easy. What does <code>sealed</code> do on a class? Why would you seal a class?	<p><code>sealed</code> prevents inheritance. Reasons to use it:</p><ul><li><b>Security</b> — prevent malicious subclass overrides.</li><li><b>Performance</b> — JIT can devirtualize and inline calls.</li><li><b>Design clarity</b> — signals the class is not designed for extension.</li></ul><p>Many framework types are sealed — e.g. <code>string</code>.</p>
S01.03.Easy. What is the difference between <code>IEnumerable<T></code> and <code>IList<T></code>? When do you choose one over the other?	<ul><li><b><code>IEnumerable<T></code></b> — read-only, forward-only, lazy — supports deferred execution.</li><li><b><code>IList<T></code></b> — adds indexing, <code>Count</code>, <code>Add</code>/<code>Remove</code> — materialized in memory.</li></ul><p>Return <code>IEnumerable<T></code> when consumers only iterate; use <code>IList<T></code> when you need random access or mutation.</p>
S01.04.Easy. What does <code>async void</code> do differently than <code>async Task</code>? Why is <code>async void</code> dangerous?	<ul><li><b><code>async void</code></b> — can't be awaited, exceptions crash the process (no caller to catch them), fire-and-forget.</li><li><b><code>async Task</code></b> — awaitable, exceptions propagate normally to the caller.</li></ul><p><code>async void</code> is only acceptable for event handlers.</p><p>https://claude.ai/chat/5bd1eb7b-a65f-42ec-80a8-9043d925b1e8</p>
S01.05.Easy. Explain boxing and unboxing. Give one example where boxing happens implicitly in C#.	<p>Boxing wraps a value type in a heap-allocated <code>object</code>. Unboxing extracts it back. Implicit boxing: <code>int x = 42; object o = x;</code> — also happens with <code>ArrayList.Add(42)</code>, <code>string.Format("{0}", 42)</code>, and casting value types to interfaces.</p>
S01.06.Medium. What does this code print and why?  ``<code>csharp string a = "hello"; string b = "hello"; string c = new string("hello".ToCharArray());  Console.WriteLine(a == b); Console.WriteLine(a == c); Console.WriteLine(ReferenceEquals(a, b)); Console.WriteLine(ReferenceEquals(a, c)); </code>``	<p><code>True, True, True, False</code>. <code>==</code> for strings does value comparison. <code>a</code> and <code>b</code> reference the same interned string literal, so <code>ReferenceEquals</code> is True. <code>c</code> is a new string object with the same value — <code>==</code> is True (value) but <code>ReferenceEquals</code> is False (different heap object).</p>
S01.07.Medium. You have a <code>List<Order></code> with 50,000 orders. Find all where <code>Status == "Shipped"</code> and <code>Total > 100</code>, sorted by <code>Total</code> descending, top 10. Write the LINQ query. Does LINQ evaluate lazily or eagerly? When does it execute?	<pre><code>var result = orders     .Where(o =&gt; o.Status == "Shipped" &amp;&amp; o.Total &gt; 100)     .OrderByDescending(o =&gt; o.Total)     .Take(10)     .ToList();</code></pre><p>The query builds lazily via <code>Where</code>, <code>OrderByDescending</code>, <code>Take</code> — these return <code>IEnumerable<T></code> and compose a pipeline. Execution is deferred until <code>.ToList()</code> forces materialization. Without <code>.ToList()</code>, iterating the result also triggers execution. <code>OrderByDescending</code> must buffer all matching items to sort.</p>
S01.08.Medium. What is the difference between <code>Task.Run()</code> and <code>Task.Factory.StartNew()</code>? When would you explicitly choose one over the other?	<ul><li><b><code>Task.Run</code></b> — shorthand with safe defaults: thread pool, <code>DenyChildAttach</code>, <code>TaskScheduler.Default</code>. Use for 99% of cases.</li><li><b><code>Task.Factory.StartNew</code></b> — fine-grained control over <code>LongRunning</code>, custom schedulers, creation options.</li></ul><p>Choose <code>StartNew</code> only for long-running CPU-bound work or custom task schedulers.</p>
S01.09.Medium. Explain the difference between <code>ConfigureAwait(false)</code> and the default <code>ConfigureAwait(true)</code>. In what context does this matter? Does it matter in ASP.NET Core?	<p><code>ConfigureAwait(true)</code> (default) resumes on the captured SynchronizationContext. <code>ConfigureAwait(false)</code> resumes on any thread pool thread. Matters in UI apps (WPF/WinForms) and old ASP.NET (had a SyncContext). ASP.NET Core has NO SyncContext, so <code>ConfigureAwait(false)</code> is unnecessary there — but library code should still use it for portability.</p>
S01.10.Medium. What is the <code>IDisposable</code> pattern? What happens if you forget to dispose an <code>HttpClient</code> in a loop? How does <code>IHttpClientFactory</code> solve this?	<p><code>IDisposable</code> provides deterministic cleanup via <code>Dispose()</code> / <code>using</code>. Creating/disposing <code>HttpClient</code> in a loop causes socket exhaustion — sockets linger in <code>TIME_WAIT</code>. <code>IHttpClientFactory</code> pools <code>HttpMessageHandler</code> instances (2min default lifetime), recycles them for DNS changes, and lets you create <code>HttpClient</code> instances cheaply without socket exhaustion.</p>
S01.11.Medium. What does this code do? Is there a bug?  ``<code>csharp public async Task<List<Product>> GetAllAsync() {     var tasks = productIds.Select(id => GetByIdAsync(id));     var results = await Task.WhenAll(tasks);     return results.ToList(); } </code>``	<p>It fetches all products in parallel using <code>Task.WhenAll</code>. The subtle bug: <code>Select</code> with an async lambda creates tasks immediately — if <code>productIds</code> is large, this fires ALL requests simultaneously (no throttling). Could overwhelm the server. Fix: use <code>SemaphoreSlim</code> or <code>Parallel.ForEachAsync</code> with <code>MaxDegreeOfParallelism</code>. Also: multiple enumeration risk if <code>tasks</code> is lazy.</p>
S01.12.Medium. What is the difference between <code>throw;</code> and <code>throw ex;</code> in a catch block? Why does it matter?	<p><code>throw;</code> preserves the original stack trace. <code>throw ex;</code> resets the stack trace to the current catch block, losing the original call site. Always use <code>throw;</code> to re-throw. <code>throw ex;</code> makes debugging much harder because you can't see where the exception originated.</p>
S01.13.Medium. You have a service registered as <code>Scoped</code>. A <code>Singleton</code> service tries to inject it. What happens? What is the name of this problem?	<p>This is called a <b>Captive Dependency</b>. The Scoped service gets captured by the Singleton and lives forever — it never gets disposed/recreated per request. This causes stale data, thread-safety issues, and DbContext tracking bugs. ASP.NET Core throws an <code>InvalidOperationException</code> if <code>ValidateScopes</code> is enabled (default in Development).</p>
S01.14.Hard. Explain the .NET garbage collector's generational model. What are Gen 0, Gen 1, Gen 2? What triggers a collection? What is the Large Object Heap and why does it matter?	<p>Gen 0: short-lived objects (locals, temp strings) — collected frequently and fast. Gen 1: buffer between short/long-lived. Gen 2: long-lived objects — collected rarely and expensive. Objects surviving a collection get promoted. Triggered when Gen 0 budget is exceeded. LOH holds objects ≥85KB, collected with Gen 2, not compacted by default (fragmentation risk). <code>GCSettings.LargeObjectHeapCompactionMode</code> can force compaction.</p>
S01.15.Hard. What is <code>Span<T></code> and why was it introduced? How does it reduce allocations compared to <code>Substring()</code>? Write a code example that parses a comma-separated string using <code>Span<T></code> without allocating new strings.	<p><code>Span<T></code> is a stack-only ref struct providing a type-safe view over contiguous memory (arrays, strings, native buffers) without copying. <code>Substring()</code> allocates a new string each time; <code>Span<T>.Slice()</code> just moves pointers — zero allocation. Key: <code>Span<T></code> can't be stored on the heap (no class fields, no async), enabling safe stack-only memory access.</p><pre><code>ReadOnlySpan&lt;char&gt; input = "alice,bob,carol"; while (input.Length &gt; 0) {     int comma = input.IndexOf(',');     ReadOnlySpan&lt;char&gt; name = comma == -1 ? input : input.Slice(0, comma);     Console.WriteLine(name.ToString());     input = comma == -1 ? ReadOnlySpan&lt;char&gt;.Empty : input.Slice(comma + 1); }</code></pre>
S01.16.Hard. You see this in a code review. What are the two subtle problems? How would you fix each?  ``<code>csharp public class OrderProcessor {     private static readonly HttpClient _client = new HttpClient();      public async Task ProcessAsync(Order order)     {         var response = await _client.PostAsJsonAsync("/api/process", order);         response.EnsureSuccessStatusCode();     } } </code>``	<p><b>Problem 1:</b> Static <code>HttpClient</code> never refreshes DNS — if the target IP changes, requests go to the stale address. Fix: use <code>IHttpClientFactory</code> or set <code>PooledConnectionLifetime</code>.</p><p><b>Problem 2:</b> No base address, no timeout, no resilience. <code>EnsureSuccessStatusCode</code> throws a generic exception with no detail. Fix: configure <code>BaseAddress</code>, add Polly retry policy, read error body before throwing.</p>
S01.17.Hard. Explain <code>ValueTask<T></code> vs <code>Task<T></code>. When is <code>ValueTask<T></code> faster? When is it dangerous? What happens if you <code>await</code> a <code>ValueTask<T></code> twice?	<p><code>ValueTask<T></code> avoids allocation when the result is already available synchronously — it wraps either a <code>T</code> value or a <code>Task<T></code>. Faster in hot paths with cache hits. Dangerous: must only be awaited ONCE. Awaiting twice is undefined behavior — may throw, return wrong result, or corrupt state. Can't <code>.Result</code> or <code>.GetAwaiter()</code> concurrently. Use <code>.AsTask()</code> if you need to store/await multiple times.</p>
S01.18.Hard. What are <code>record</code> types in C#? How do they differ from classes in terms of equality, immutability, and generated code? What is <code>with</code> expression? When would you use <code>record struct</code> vs <code>record class</code>?	<p>Records provide value-based equality (all properties compared), auto-generated <code>ToString</code> (human-readable), <code>Deconstruct</code>, and <code>with</code> expressions for non-destructive mutation. <code>record class</code> is a reference type with immutability via <code>init</code> properties. <code>record struct</code> is a value type — good for small, frequently-copied data. Records are ideal for DTOs, events, and immutable domain objects.</p>
S01.19.Hard. You have a hot code path that creates thousands of small temporary objects per request. The GC is causing latency spikes. What strategies can you use to reduce GC pressure? Name at least four.	<li><code>ArrayPool<T>.Shared</code> / <code>ObjectPool<T></code> — rent and return instead of alloc/GC.</li><li><code>Span<T></code> + <code>stackalloc</code> — stack allocation, zero GC.</li><li>Use structs for small, short-lived data.</li><li><code>StringBuilder</code> pooling or <code>string.Create</code>.</li><li>Avoid LINQ in hot paths (allocates iterators/delegates).</li><li><code>RecyclableMemoryStream</code> for streams.</li><li>Cache frequently-used objects.</li><li>Use <code>ref struct</code> / <code>ref returns</code> to avoid copies.</li>
