No password is stored or transmitted.</p><p><b>Production consequence:</b> a leaked client secret grants persistent access until manually rotated. A leaked OIDC token is useless after minutes — and is scoped to one workflow run.</p></div></div><div class="rf"><p class="rf-label">🚩 Red Flag — shallow answer</p><div class="ac"><p>"OIDC is just another password stored differently." Wrong — it's a fundamentally different trust model. No credential is stored; trust is asserted cryptographically via GitHub's identity.</p></div></div><div class="gf"><p class="gf-label">✓ Green Flag — pro insight</p><div class="ac"><p>Mentioning that OIDC tokens are bound to the specific repository, branch, and environment. A token generated for <code class="c">main</code> cannot be used by a forked repo or a different branch — unlike a static secret that any holder can use from anywhere.</p></div></div>

`npm ci` can only install packages when your package.json and package-lock.json are in sync</code></pre><p><b>Fix:</b> run <code class="c">npm install</code> locally to regenerate <code class="c">package-lock.json</code>, commit it, then re-run CI.</p><p><b>Other causes (less common):</b></p><ul><li><code class="c">node_modules</code> checked into the repo — <code class="c">npm ci</code> deletes and reinstalls, but a dirty state can cause conflicts</li><li>Node version mismatch between local and CI (<code class="c">engines</code> field in <code class="c">package.json</code>)</li></ul></div></div><div class="rf"><p class="rf-label">🚩 Red Flag — shallow answer</p><div class="ac"><p>Switching back to <code class="c">npm install</code> on CI to "fix" the error. That defeats the purpose — <code class="c">npm install</code> will silently install different versions than <code class="c">package-lock.json</code> specifies, re-introducing version drift. The lock file must be fixed, not bypassed.</p></div></div><div class="gf"><p class="gf-label">✓ Green Flag — pro insight</p><div class="ac"><p>Mentioning that <code class="c">npm ci</code> is intentionally strict: if it passes, every developer and every CI run installs byte-for-byte identical packages. This makes "works on my machine" dependency bugs impossible to hide — the lock file IS the reproducibility contract.</p></div></div>
