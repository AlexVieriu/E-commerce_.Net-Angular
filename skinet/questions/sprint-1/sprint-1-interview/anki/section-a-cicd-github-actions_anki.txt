Why is it safer than a stored client secret?</div></div>	<style>.c{background:#3e4451;color:#56b6c2;padding:1px 6px;border-radius:4px;font-family:monospace;font-size:.88em}.p{background:#282c34;color:#abb2bf;padding:12px 16px;border-radius:6px;border-left:3px solid #61afef;font-family:monospace;font-size:13px;white-space:pre-wrap;word-break:break-word;margin:10px 0;display:block}.ac{font-family:system-ui,-apple-system,sans-serif;line-height:1.65;font-size:0.95em;text-align:left}.ac p{margin:.4em 0}.ac ul,.ac ol{margin:.4em 0;padding-left:1.6em}.ac li{margin:.35em 0}.ac li>p{margin:0}.ac b{color:#56b6c2}.ac li::marker{color:#61afef}.rf{border-left:3px solid #e06c75;background:#2a1f22;padding:10px 14px;border-radius:0 6px 6px 0;margin:14px 0}.rf-label{color:#e06c75;font-family:monospace;font-size:0.72em;font-weight:700;letter-spacing:0.08em;text-transform:uppercase;margin:0 0 6px}.gf{border-left:3px solid #98c379;background:#1b2b1e;padding:10px 14px;border-radius:0 6px 6px 0;margin:14px 0}.gf-label{color:#98c379;font-family:monospace;font-size:0.72em;font-weight:700;letter-spacing:0.08em;text-transform:uppercase;margin:0 0 6px}.af{border-left:3px solid #61afef;background:#1e2430;padding:10px 14px;border-radius:0 6px 6px 0;margin:0 0 14px}.af-label{color:#61afef;font-family:monospace;font-size:0.72em;font-weight:700;letter-spacing:0.08em;text-transform:uppercase;margin:0 0 6px}</style><div class="af"><p class="af-label">★ The 5% Answer</p><div class="ac"><ul><li><b>OIDC (OpenID Connect)</b> — GitHub and Azure establish a trust relationship via a <b>federated credential</b> on a Managed Identity. No password is stored anywhere.</li><li>GitHub requests a <b>short-lived token</b> per workflow run from Azure's STS. The token is scoped to the run and expires within minutes.</li><li>Compare to a stored client secret: stored in GitHub Secrets as a long-lived credential, must be manually rotated, and is compromised if the secret store is breached.</li></ul><pre class="p"><code>- uses: azure/login@v2<br>  with:<br>    client-id: ${{ secrets.AZURE_CLIENT_ID }}       # identifier, not a secret<br>    tenant-id: ${{ secrets.AZURE_TENANT_ID }}<br>    subscription-id: ${{ secrets.AZURE_SUBSCRIPTION_ID }}</code></pre><p>These are IDs — not credentials. No password is stored or transmitted.</p><p><b>Production consequence:</b> a leaked client secret grants persistent access until manually rotated. A leaked OIDC token is useless after minutes — and is scoped to one workflow run.</p></div></div><div class="rf"><p class="rf-label">🚩 Red Flag — shallow answer</p><div class="ac"><p>"OIDC is just another password stored differently." Wrong — it's a fundamentally different trust model. No credential is stored; trust is asserted cryptographically via GitHub's identity.</p></div></div><div class="gf"><p class="gf-label">✓ Green Flag — pro insight</p><div class="ac"><p>Mentioning that OIDC tokens are bound to the specific repository, branch, and environment. A token generated for <code class="c">main</code> cannot be used by a forked repo or a different branch — unlike a static secret that any holder can use from anywhere.</p></div></div>

<div style="text-align:left"><div style="font-family:monospace;font-size:0.68em;color:#5c6370;margin-bottom:10px;letter-spacing:0.03em">S01.05 · <span style="background:#d19a66;color:#282c34;padding:2px 9px;border-radius:12px;font-size:0.7em;font-weight:700;font-family:sans-serif;vertical-align:middle;letter-spacing:0.06em;text-transform:uppercase">Medium</span> · <span style="background:#986801;color:#fff;padding:2px 9px;border-radius:12px;font-size:0.7em;font-weight:700;font-family:sans-serif;vertical-align:middle;letter-spacing:0.06em;text-transform:uppercase">◆ MED</span></div><div style="font-family:system-ui,-apple-system,sans-serif;font-size:1.08em;line-height:1.55">[OUT-OF-SCOPE] <code style="background:#3e4451;color:#56b6c2;padding:1px 6px;border-radius:4px;font-family:monospace;font-size:0.88em">npm install</code> passes on CI but installs a different version than local. If <code class="c">"@angular/core": "^18.0.0"</code> and a new patch <code class="c">18.0.3</code> was released between the developer's last <code class="c">npm install</code> and the CI run, CI installs <code class="c">18.0.3</code> while local has <code class="c">18.0.1</code>.</p><p><b>How <code class="c">npm ci</code> prevents it:</b></p><ul><li>Reads <code class="c">package-lock.json</code> <b>exactly</b> — no range resolution</li><li>If <code class="c">package.json</code> and <code class="c">package-lock.json</code> are out of sync, <code class="c">npm ci</code> <b>fails</b> immediately, forcing an intentional update</li><li>Deletes <code class="c">node_modules</code> before installing — guarantees a clean state, no leftover artefacts</li></ul><p><b>Practical failure mode:</b></p><pre class="p"><code>Local:  @angular/material@18.0.1 (installed 3 months ago)<br>CI:     @angular/material@18.2.0 (latest in ^18 range)<br>→ Angular build passes locally, fails on CI due to breaking change in 18.2.0</code></pre></div></div><div class="rf"><p class="rf-label">🚩 Red Flag — shallow answer</p><div class="ac"><p>"Commit <code class="c">node_modules</code> to avoid version drift."
