S08.01.Medium. This code has a race condition. Identify it and explain how <code>[ConcurrencyCheck]</code> fixes it:  ``<code>csharp public async Task PlaceOrder(int productId, int quantity) {     var product = await _context.Products.FindAsync(productId);     if (product.QuantityInStock >= quantity)     {         product.QuantityInStock -= quantity;         await _context.SaveChangesAsync();     } } </code>``	<p><b>The race condition:</b> two concurrent requests both read <code>QuantityInStock = 1</code>. Both pass the <code>>= quantity</code> check (assuming quantity=1). Both decrement, resulting in <code>QuantityInStock = -1</code>. One item sold twice.</p><p><b>How <code>[ConcurrencyCheck]</code> fixes it:</b></p><pre><code>public class Product {     [ConcurrencyCheck]     public int QuantityInStock { get; set; } }</code></pre><p>EF Core now generates: <code>UPDATE Products SET QuantityInStock = @new WHERE Id = @id AND QuantityInStock = @original</code></p><ul><li>Request 1 updates from 1 → 0. Succeeds (1 row affected).</li><li>Request 2 tries to update from 1 → 0, but the DB now shows 0. 0 rows affected → EF throws <code>DbUpdateConcurrencyException</code>.</li><li>Catch the exception → return 409 Conflict → user sees "item sold out."</li></ul>
S08.02.Medium. This Angular code doesn't update the template. Why? Fix it.  ``<code>typescript @Component({   template: </code><p>{{ user().name }}</p>              <button (click)="rename()">Rename</button><code> }) export class UserComponent {   user = signal({ name: 'Alex', age: 25 });    rename() {     this.user.update(u => {       u.name = 'Bob';       return u;     });   } } </code>``	<p><b>Why it doesn't update:</b> the signal holds an object reference. <code>update()</code> mutates the SAME object (<code>u.name = 'Bob'</code>) and returns the same reference. Angular's signal equality check uses <code>===</code> — same reference → no change detected → template does not re-render.</p><p><b>Fix:</b> return a NEW object instead of mutating the existing one:</p><pre><code>rename() {   this.user.update(u =&gt; ({ ...u, name: 'Bob' })); }</code></pre><p>The spread creates a new object at a new memory address. <code>===</code> comparison fails → signal sees a change → template re-renders with <code>Bob</code>.</p>
S08.03.Hard. This test passes but is worthless. Explain exactly why, step by step:  ``<code>csharp [Fact] public async Task DeleteCart_WhenCalled_ReturnsTrue() {     _mockDb.Setup(x => x.KeyDeleteAsync(         It.IsAny<RedisKey>(),         It.IsAny<CommandFlags>()))         .ReturnsAsync(true);      var result = await _cartService.DeleteCartAsync("cart-1");      result.Should().BeTrue(); } </code>`<code>  Now: what if the production code calls </code>KeyDeleteAsync<code> through the </code>IDatabaseAsync` explicit interface? What changes?	<p><b>Why it's worthless — step by step:</b></p><li><code>Setup</code> configures what <code>KeyDeleteAsync</code> returns <i>if called</i> — it's not an assertion that it WILL be called.</li><li><code>DeleteCartAsync</code> is invoked.</li><li><code>result.Should().BeTrue()</code> only checks the return value of the SERVICE method — not whether Redis was called.</li><li><b>No <code>Verify</code></b> — nothing asserts that <code>KeyDeleteAsync</code> was actually invoked.</li><li>If <code>DeleteCartAsync</code> is rewritten to return <code>true</code> without calling Redis at all, this test still passes.</li><li>If <code>DeleteCartAsync</code> is deleted entirely → compile error, but that's the compiler, not the test.</li><p>The test proves "the method returns <code>true</code>" and nothing else. It does not prove Redis was called, the correct key was used, or any deletion actually happened.</p><p><b>If production code calls through <code>IDatabaseAsync</code> explicit interface:</b></p><p><code>_mockDb</code> is <code>Mock<IDatabase></code>. The <code>Setup</code> targets <code>IDatabase.KeyDeleteAsync</code>. If the code calls <code>((IDatabaseAsync)_db).KeyDeleteAsync(...)</code>, Moq looks for a setup on the <code>IDatabaseAsync</code> interface face of the mock — finds none → returns default (<code>false</code>). Now <code>result.Should().BeTrue()</code> FAILS. The test was broken all along but for the wrong reasons — it was passing only because the setup accidentally matched the non-async overload being called directly on <code>IDatabase</code>.</p>
S08.04.Hard. Read this code carefully. There are three bugs. Find all three:  ``<code>csharp public async Task<Order?> CreateOrderAsync(string buyerEmail, CreateOrderDto dto) {     var cart = await _cartService.GetCartAsync(dto.CartId);     var items = new List<OrderItem>();      foreach (var cartItem in cart.Items)     {         var product = await _context.Products.FindAsync(cartItem.ProductId);         var item = new OrderItem(product.Name, product.Price, cartItem.Quantity);         items.Add(item);         product.QuantityInStock -= cartItem.Quantity;     }      var order = new Order(buyerEmail, dto.ShippingAddress, dto.DeliveryMethodId, items);     _context.Orders.Add(order);     await _context.SaveChangesAsync();      return order; } </code>``	<p><b>Bug 1: <code>cart</code> can be null — no null check.</b></p><p><code>GetCartAsync</code> returns <code>null</code> if the cart doesn't exist (expired, wrong ID). <code>cart.Items</code> throws <code>NullReferenceException</code>. Fix: <code>if (cart == null) return null;</code> (or throw <code>CartNotFoundException</code>).</p><p><b>Bug 2: <code>product</code> can be null — no null check.</b></p><p><code>FindAsync(cartItem.ProductId)</code> returns <code>null</code> if the product was deleted. <code>product.Name</code> throws <code>NullReferenceException</code>. Fix: <code>if (product == null) throw new ProductNotFoundException(cartItem.ProductId);</code>.</p><p><b>Bug 3: No stock validation before decrement.</b></p><p><code>product.QuantityInStock -= cartItem.Quantity</code> can go negative. There's no check that <code>product.QuantityInStock >= cartItem.Quantity</code>. Two items ordered when only one is in stock results in <code>QuantityInStock = -1</code>. Fix: add <code>if (product.QuantityInStock < cartItem.Quantity) throw new InsufficientStockException(...)</code> before the decrement.</p>
S08.05.Hard. This Angular interceptor handles errors. What happens if the login page itself makes an API call that returns 401? Describe the infinite loop and how to fix it.  ``<code>typescript export const errorInterceptor: HttpInterceptorFn = (req, next) => {   return next(req).pipe(     catchError(error => {       if (error.status === 401) {         inject(Router).navigateByUrl('/account/login');       }       if (error.status === 400) {         inject(SnackbarService).error(error.error.message);       }       return throwError(() => error);     })   ); }; </code>``	<p><b>The infinite loop:</b></p><li>User is on <code>/account/login</code></li><li>Login form calls <code>POST /api/account/login</code> with wrong password → API returns 401</li><li>Interceptor catches 401 → <code>router.navigateByUrl('/account/login')</code></li><li>Angular navigates to <code>/account/login</code> again → component reinitialises → might make another API call → 401 → navigate again → repeat</li><p>Even without an explicit API call on init, Angular re-renders the login component each time, which can trigger <code>ngOnInit</code> HTTP calls (e.g. "check if token exists" or "load OAuth config").</p><p><b>Fix:</b> skip the 401 navigation if the request URL is the login endpoint, or if the user is already on the login page:</p><pre><code>if (error.status === 401 &amp;&amp; !req.url.includes('/account/login')) {   inject(Router).navigateByUrl('/account/login'); }</code></pre>
