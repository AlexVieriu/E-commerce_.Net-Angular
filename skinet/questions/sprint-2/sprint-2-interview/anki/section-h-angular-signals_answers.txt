# H2 — [EASY][HIGH] What's the difference between zone-based Angular and zoneless?
# ────────────────────────────────────────────────────────────────────────────
<style>.c{background:#3e4451;color:#56b6c2;padding:1px 6px;border-radius:4px;font-family:monospace;font-size:.88em}.p{background:#282c34;color:#abb2bf;padding:12px 16px;border-radius:6px;border-left:3px solid #61afef;font-family:monospace;font-size:13px;white-space:pre-wrap;word-break:break-word;margin:10px 0;display:block}.ac{font-family:system-ui,-apple-system,sans-serif;line-height:1.65;font-size:0.95em;text-align:left}.ac p{margin:.4em 0}.ac ul,.ac ol{margin:.4em 0;padding-left:1.6em}.ac li{margin:.35em 0}.ac li>p{margin:0}.ac b{color:#56b6c2}.ac li::marker{color:#61afef}.rf{border-left:3px solid #e06c75;background:#2a1f22;padding:10px 14px;border-radius:0 6px 6px 0;margin:14px 0}.rf-label{color:#e06c75;font-family:monospace;font-size:0.72em;font-weight:700;letter-spacing:0.08em;text-transform:uppercase;margin:0 0 6px}.gf{border-left:3px solid #98c379;background:#1b2b1e;padding:10px 14px;border-radius:0 6px 6px 0;margin:14px 0}.gf-label{color:#98c379;font-family:monospace;font-size:0.72em;font-weight:700;letter-spacing:0.08em;text-transform:uppercase;margin:0 0 6px}.af{border-left:3px solid #61afef;background:#1e2430;padding:10px 14px;border-radius:0 6px 6px 0;margin:0 0 14px}.af-label{color:#61afef;font-family:monospace;font-size:0.72em;font-weight:700;letter-spacing:0.08em;text-transform:uppercase;margin:0 0 6px}</style><div class="af"><p class="af-label">★ The 5% Answer</p><div class="ac"><ul><li><b>Zone-based (classic, up to v17 default)</b> — Angular uses <code class="c">zone.js</code>, a global monkey-patch that intercepts all async events (clicks, timers, HTTP) and triggers change detection on every one. Mutation works because the zone catches everything.</li><li><b>Zoneless (v18+, opt-in via <code class="c">provideZonelessChangeDetection()</code>)</b> — no global monkey-patch. Change detection runs only when signals change, <code class="c">markForCheck()</code> is called, or <code class="c">ChangeDetectorRef.detectChanges()</code> is explicitly invoked.</li></ul><p>This project is zoneless — which is why mutation without creating a new reference silently fails to re-render.</p></div></div><div class="rf"><p class="rf-label">🚩 Red Flag — shallow answer</p><div class="ac"><p>"Zoneless is faster." True but shallow — it's faster <i>because</i> it doesn't poll for changes after every async event, not magically.</p></div></div><div class="gf"><p class="gf-label">✓ Green Flag — pro insight</p><div class="ac"><p>Mentioning that zoneless requires every third-party library to be <b>signal-aware or opt into change detection manually</b>. Many libraries (non-reactive ones) break subtly in zoneless mode. Migration effort is real.</p></div></div>

{<br>    state.address = true;<br>    return state;<br>});</code></pre><p><b>What happens in memory:</b></p><pre class="p"><code>Before: state @ 0x001 = { address: false, card: false, delivery: false }<br>After:  state @ 0x001 = { address: true,  card: false, delivery: false }</code></pre><p>Same memory address → same reference → <code class="c">state === state</code> is <code class="c">true</code> → Angular's signal equality check returns "no change" → <b>no re-render</b>.</p><p><b>But the value in the signal IS <code class="c">true</code></b> — the signal's internal <code class="c">.value</code> was mutated in place. # ────────────────────────────────────────────────────────────────────────────
<style>.c{background:#3e4451;color:#56b6c2;padding:1px 6px;border-radius:4px;font-family:monospace;font-size:.88em}.p{background:#282c34;color:#abb2bf;padding:12px 16px;border-radius:6px;border-left:3px solid #61afef;font-family:monospace;font-size:13px;white-space:pre-wrap;word-break:break-word;margin:10px 0;display:block}.ac{font-family:system-ui,-apple-system,sans-serif;line-height:1.65;font-size:0.95em;text-align:left}.ac p{margin:.4em 0}.ac ul,.ac ol{margin:.4em 0;padding-left:1.6em}.ac li{margin:.35em 0}.ac li>p{margin:0}.ac b{color:#56b6c2}.ac li::marker{color:#61afef}.rf{border-left:3px solid #e06c75;background:#2a1f22;padding:10px 14px;border-radius:0 6px 6px 0;margin:14px 0}.rf-label{color:#e06c75;font-family:monospace;font-size:0.72em;font-weight:700;letter-spacing:0.08em;text-transform:uppercase;margin:0 0 6px}.gf{border-left:3px solid #98c379;background:#1b2b1e;padding:10px 14px;border-radius:0 6px 6px 0;margin:14px 0}.gf-label{color:#98c379;font-family:monospace;font-size:0.72em;font-weight:700;letter-spacing:0.08em;text-transform:uppercase;margin:0 0 6px}.af{border-left:3px solid #61afef;background:#1e2430;padding:10px 14px;border-radius:0 6px 6px 0;margin:0 0 14px}.af-label{color:#61afef;font-family:monospace;font-size:0.72em;font-weight:700;letter-spacing:0.08em;text-transform:uppercase;margin:0 0 6px}</style><div class="af"><p class="af-label">★ The 5% Answer</p><div class="ac"><p><b>The bug:</b> <code class="c">{ ...s }</code> creates a new outer object, but <code class="c">s.user</code> is still the <b>same reference</b>. The nested mutation (<code class="c">s.user.name = 'Alex'</code>) changes the original <code class="c">user</code> object. The signal thinks it changed (outer reference is new), but <b>any derived signal or computed reading <code class="c">form().user</code> sees the same <code class="c">user</code> object</b> — if it uses its own equality check on <code class="c">user</code>, it won't detect the name change.</p><p>Worse: if any other code holds a reference to the original <code class="c">form().user</code>, they see the mutation silently propagate.</p><p><b>Fix — deep spread the nested object:</b></p><pre class="p"><code>form.update(s =&gt; ({ ...s, user: { ...s.user, name: 'Alex' } }));</code></pre><p>Memory after fix:</p><pre class="p"><code>Before: { user: @0x001, submitted: ... }  where @0x001 = { name: '', ... }<br>After:  { user: @0x002, submitted: ... }  where @0x002 = { name: 'Alex', ... }<br>Both outer and inner objects have new references.</code></pre><p><b>Deep updates beyond 2 levels</b> become painful with manual spreading. For deeply nested state, reach for:</p><ul><li><b>Immer</b> — <code class="c">produce(state, draft =&gt; { draft.user.name = 'Alex' })</code> — looks like mutation, produces immutable updates.</li><li><b>@ngrx/signals</b> with <code class="c">patchState</code> — scoped updates with automatic immutability.</li></ul></div></div><div class="rf"><p class="rf-label">🚩 Red Flag — shallow answer</p><div class="ac"><p>"Wrap in JSON.parse(JSON.stringify(s))." Destroys class instances, doesn't handle dates/maps/symbols, and is massively slower than targeted spreads.</p></div></div><div class="gf"><p class="gf-label">✓ Green Flag — pro insight</p><div class="ac"><p>Mentioning that deeply nested form state is a <b>code smell</b> — flatten the model (one signal per form section) or use a reactive forms API. Signals are best for flat, value-oriented state.</p></div></div>

# H12 — [HARD][MEDIUM] Angular 17 shipped signal.mutate(); v18 removed it. What did it do, w...
# ────────────────────────────────────────────────────────────────────────────
<style>.c{background:#3e4451;color:#56b6c2;padding:1px 6px;border-radius:4px;font-family:monospace;font-size:.88em}.p{background:#282c34;color:#abb2bf;padding:12px 16px;border-radius:6px;border-left:3px solid #61afef;font-family:monospace;font-size:13px;white-space:pre-wrap;word-break:break-word;margin:10px 0;display:block}.ac{font-family:system-ui,-apple-system,sans-serif;line-height:1.65;font-size:0.95em;text-align:left}.ac p{margin:.4em 0}.ac ul,.ac ol{margin:.4em 0;padding-left:1.6em}.ac li{margin:.35em 0}.ac li>p{margin:0}.ac b{color:#56b6c2}.ac li::marker{color:#61afef}.rf{border-left:3px solid #e06c75;background:#2a1f22;padding:10px 14px;border-radius:0 6px 6px 0;margin:14px 0}.rf-label{color:#e06c75;font-family:monospace;font-size:0.72em;font-weight:700;letter-spacing:0.08em;text-transform:uppercase;margin:0 0 6px}.gf{border-left:3px solid #98c379;background:#1b2b1e;padding:10px 14px;border-radius:0 6px 6px 0;margin:14px 0}.gf-label{color:#98c379;font-family:monospace;font-size:0.72em;font-weight:700;letter-spacing:0.08em;text-transform:uppercase;margin:0 0 6px}.af{border-left:3px solid #61afef;background:#1e2430;padding:10px 14px;border-radius:0 6px 6px 0;margin:0 0 14px}.af-label{color:#61afef;font-family:monospace;font-size:0.72em;font-weight:700;letter-spacing:0.08em;text-transform:uppercase;margin:0 0 6px}</style><div class="af"><p class="af-label">★ The 5% Answer</p><div class="ac"><p><b>What <code class="c">mutate()</code> claimed to do:</b></p><pre class="p"><code>// Angular 17<br>const cart = signal({ items: [] });<br>cart.mutate(c =&gt; c.items.push(newItem));  // push directly, signal "knows"</code></pre><p>The API let you mutate the value in place without returning a new reference, and manually notified dependents that the value had "changed." On paper: ergonomic. No spread gymnastics.</p><p><b>Why it was a trap:</b></p><ol><li><b>It bypassed reference equality — the ONE invariant the rest of the signal ecosystem relied on.</b> <code class="c">computed</code>, <code class="c">effect</code>, and the change detector all use <code class="c">===</code>. <code class="c">mutate</code> told them "trust me, it changed" without changing the reference.</li></ol><ol><li><b>Downstream <code class="c">computed</code> signals memoised on reference.</b> If <code class="c">computed(() =&gt; cart().items.length)</code> cached against the old array reference, a subsequent <code class="c">.length</code> read returned the CACHED value — because the reference was still <code class="c">===</code> equal to what was memoised.</li></ol><ol><li><b>RxJS interop (<code class="c">toObservable</code>) broke silently.</b> The observable emits on reference change. <code class="c">mutate</code> didn't produce one. Subscribers saw no emission even though the value "changed."</li></ol><ol><li><b>It trained the wrong mental model.</b> Developers learned "signals are containers I can mutate," generalised that to <code class="c">signal()....push()</code> (which doesn't work), and then couldn't debug why their real signal updates didn't re-render.</li></ol><p><b>Why it was removed (v18):</b></p><p>The Angular team chose consistency over ergonomics. One rule for signal identity (<code class="c">===</code> on the value) is simpler to reason about than "sometimes reference-based, sometimes notification-based." The API surface shrank; the mental model got cleaner.</p><p><b>The API design lesson:</b></p><ul><li><b>An optimisation that requires users to violate the system's invariant is not an optimisation — it's a foot-gun.</b> <code class="c">mutate</code> saved three characters of spread syntax at the cost of making the signal model inconsistent.</li><li><b>Reactive systems need ONE source of truth for "did it change."</b> Signals picked <code class="c">===</code>. Anything that claims to be a signal update must respect that rule.</li><li><b>Removing an API is a legitimate design move.</b> Teams that ship broken APIs and let them linger to "avoid breaking changes" accumulate a worse kind of debt: confused users.</li></ul><p><b>Modern replacement:</b></p><pre class="p"><code>// v18+ — no mutate, always produce new reference<br>cart.update(c =&gt; ({ ...c, items: [...c.items, newItem] }));</code></pre><p>Immer or signal-store libraries give you the ergonomic feel without breaking the invariant — they do the immutable update under the hood but present a mutation-style API.</p></div></div><div class="rf"><p class="rf-label">🚩 Red Flag — shallow answer</p><div class="ac"><p>"They removed it because nobody used it." They removed it because it was subtly broken. Popularity wasn't the issue — correctness was.</p></div></div><div class="gf"><p class="gf-label">✓ Green Flag — pro insight</p><div class="ac"><p>Mentioning that the same bug class exists in other reactive systems — Vue's <code class="c">reactive()</code> proxies mutations automatically (works), MobX observes property access via Proxy (works), but anything that tries to combine "identity-based change detection" with "in-place mutation" will hit the same wall. The lesson generalises: pick a model and enforce it at the API boundary.</p></div></div>
