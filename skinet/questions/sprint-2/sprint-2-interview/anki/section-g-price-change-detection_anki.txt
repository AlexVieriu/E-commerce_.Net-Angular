S07.01.Medium. A user adds an item at $50 to their cart. Before checkout, the admin changes the price to $60. The user clicks "Place Order." What should happen? What HTTP status code? What does the user see?	<p>The <code>OrderService</code> should compare each cart item's stored price against the current product price in the DB. If any mismatch is found:</p><ul><li>Return <b>409 Conflict</b> — the cart state conflicts with current product state</li><li>Response body: <code>{ "type": "PriceConflict", "message": "Prices have changed. Please review your cart." }</code></li><li>Angular: show a dialog listing the changed items with old → new prices, with a "Review Cart" button</li><li>User must acknowledge the change before proceeding — the cart is updated with the new prices</li></ul><p>The order is <b>not created</b>. The user is shown the updated price and must re-confirm.</p>
S07.02.Medium. Why return 409 (Conflict) instead of 400 (Bad Request) for a price mismatch? What's the semantic difference?	<ul><li><b>400 Bad Request</b> — the client sent malformed or invalid data. The request itself is wrong (missing field, wrong format, validation failure). The client should fix their request.</li><li><b>409 Conflict</b> — the request is syntactically valid but conflicts with the current state of the server. The client's data was correct when they assembled it, but the server's state has changed.</li></ul><p>A price mismatch is a <b>state conflict</b> — the cart was built with $50 (correct at that moment), but the server now says $60. The request is well-formed. The problem is the world changed between cart creation and checkout. That's 409.</p><p>Using 400 would mislead the client into thinking their request was badly formed and they need to re-enter data. 409 tells them to sync with the server's current state.</p>
