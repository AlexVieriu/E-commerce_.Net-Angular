S03.01.Easy. What is a signal in Angular? How is it different from a BehaviorSubject?	<ul><li><b>Signal</b> — a reactive value wrapper; read with <code>count()</code>, write with <code>.set()</code> / <code>.update()</code>. Angular tracks which templates and <code>computed()</code> signals read it and re-evaluates only those.</li><li><b>BehaviorSubject</b> — an RxJS observable holding a current value; you must <code>.subscribe()</code> to react, manually <code>.unsubscribe()</code> to avoid memory leaks, and use <code>async</code> pipe or <code>takeUntilDestroyed</code> in components.</li><li><b>Key difference</b> — signals are <b>synchronous, pull-based, and automatically tracked</b> by Angular's rendering engine. BehaviorSubject is <b>push-based, requires subscription management</b>, and isn't natively integrated with change detection.</li></ul>
S03.02.Easy. What does <code>computed()</code> do? When does it re-evaluate?	<p><code>computed()</code> creates a derived signal whose value is calculated from other signals. It re-evaluates <b>lazily</b> — only when one of its signal dependencies changes AND the computed value is read. Angular tracks the signals accessed during the computation function and marks the computed as stale when any of them change. Reading a stale computed triggers re-evaluation; if no dependency changed, the cached value is returned immediately.</p>
S03.03.Easy. Why does mutating a signal object not trigger re-render in Angular?	<p>Signals use <b>reference equality</b> by default. When you mutate an object in-place (e.g., <code>cart.push(item)</code>), the object reference doesn't change — it's still the same array/object in memory. Angular compares the new value to the old value using <code>===</code>. Since the reference is identical, Angular sees "value unchanged" and no re-render is triggered. You must replace the reference by creating a new object/array to make the signal detect a change.</p>
S03.04.Medium. What does this code output? Why?  ``<code>typescript const count = signal(0); const doubled = computed(() => count() * 2); const isEven = computed(() => doubled() % 2 === 0);  console.log(isEven()); // ? count.set(3); console.log(isEven()); // ? count.set(4); console.log(isEven()); // ? </code>``	<pre><code>true   // 0 * 2 = 0, 0 % 2 === 0 → true true   // 3 * 2 = 6, 6 % 2 === 0 → true true   // 4 * 2 = 8, 8 % 2 === 0 → true</code></pre><p>All outputs are <code>true</code>. <code>doubled</code> is always even (any integer × 2 is divisible by 2), so <code>isEven</code> is always <code>true</code> regardless of <code>count</code>. The dependency chain is: <code>count</code> → <code>doubled</code> → <code>isEven</code>. Angular's signal graph evaluates lazily and correctly through the chain.</p>
S03.05.Medium. You have a signal holding a shopping cart:  ``<code>typescript const cart = signal<CartItem[]>([]); </code>`<code>  Write a function </code>addItem(item: CartItem)` that correctly triggers re-render. Write a version that DOESN'T trigger re-render. Explain the difference.	<pre><code>// CORRECT — creates new array reference function addItem(item: CartItem) {     cart.update(items =&gt; [...items, item]); }  // WRONG — mutates in place, no re-render function addItemBroken(item: CartItem) {     cart().push(item); }</code></pre><p>The difference: <code>.update()</code> calls the signal's setter with a new array value (<code>[...items, item]</code>). Angular's <code>Object.is</code> comparison sees a new reference and triggers re-render. <code>.push()</code> mutates the existing array — the reference stays the same, Angular's equality check returns <code>true</code>, no update fires.</p>
S03.06.Medium. What is <code>effect()</code> in Angular signals? When does it run? What are the rules about writing to signals inside an effect? Why does Angular restrict this?	<ul><li><b>What it does</b> — runs a function whenever any signal it reads changes. Executes once immediately on creation (to establish dependencies), then again on each dependency change.</li><li><b>Rules</b> — you cannot write to signals inside an effect by default. Angular throws <code>NG0600: Writing to signals is not allowed in a reactive context</code>. To allow it, pass <code>{ allowSignalWrites: true }</code>.</li><li><b>Why</b> — writing to a signal inside an effect creates a potential feedback loop: the write triggers other effects/computed, which could re-trigger the original effect, causing infinite loops or unpredictable evaluation order.</li></ul>
S03.07.Medium. You have a component using signals. You want to make an HTTP call when a signal changes. Should you use <code>effect()</code> or <code>computed()</code>? Why? What's the danger of using <code>effect()</code> for side effects that call APIs?	<p>Use <code>toObservable()</code> to convert the signal to an observable, then <code>switchMap</code> for the HTTP call — proper async handling, request cancellation on rapid changes, and error management via RxJS operators.</p><p><code>effect()</code> for HTTP is dangerous because:</p><ul><li>it doesn't cancel in-flight requests when the signal changes again (race conditions)</li><li>it has no built-in error handling</li><li>it misuses the effect API, which is for synchronous side effects</li></ul><p><code>computed()</code> is wrong because it's for synchronous derived values — it can't return a <code>Promise</code> or <code>Observable</code>.</p>
S03.08.Medium. A signal holds a nested object: <code>signal({ user: { name: '', address: { city: '' } } })</code>. You spread the outer object but mutate <code>address.city</code> directly. Does the template update? Explain the inner reference problem and the fix.	<p>It depends on what the template reads. Spreading the outer object creates a new signal value reference — the signal's equality check (<code>Object.is</code>) sees a new object and fires. Templates and computed signals that read the signal will re-evaluate. However, the inner <code>address</code> object is still the <b>same reference</b> — any <code>computed()</code> that reads <code>signal().user.address</code> and uses reference equality to check it won't detect a change. More critically, the mutation happens before <code>set()</code> is called, meaning the original signal value is also mutated (they share the <code>address</code> reference).</p><p>Fix: replace every level of nesting you change with a new object.</p>
S03.09.Medium. Create a signal with <code>{ address: boolean, payment: boolean }</code>. Write a <code>computed</code> that returns <code>true</code> only when both are <code>true</code>. Write a function that correctly sets <code>address</code> to <code>true</code>. Demonstrate what happens if you mutate instead of spread.	<pre><code>const steps = signal({ address: false, payment: false });  const canPlaceOrder = computed(() =&gt; steps().address &amp;&amp; steps().payment);  function completeAddress() {     steps.update(s =&gt; ({ ...s, address: true })); }  // BROKEN — mutation, no re-render function completeAddressBroken() {     steps().address = true; // same object reference — canPlaceOrder never updates }</code></pre>
S03.10.Hard. You have deeply nested state:  ``<code>typescript const store = signal({   user: {     profile: { name: '', address: { city: '', zip: '' } },     preferences: { theme: 'dark', notifications: true }   },   cart: { items: [], total: 0 } }); </code>`<code>  Write a function that updates ONLY </code>user.profile.address.city<code> to </code>'London'<code> while correctly triggering re-render. Now explain: if a </code>computed()<code> signal reads ONLY </code>store().cart.total`, does updating the city cause it to re-evaluate? Why?	<pre><code>function updateCity(city: string) {     store.update(s =&gt; ({         ...s,         user: {             ...s.user,             profile: {                 ...s.user.profile,                 address: {                     ...s.user.profile.address,                     city                 }             }         }     })); }</code></pre><p>A <code>computed(() => store().cart.total)</code> <b>will be marked stale</b> when <code>store</code> changes — because it reads <code>store()</code>, and <code>store</code> is a new reference after the update. However, if <code>cart.total</code> hasn't changed, Angular's computed memoization will return the cached value and <b>skip re-rendering</b> any templates that depend on it. The computed re-evaluates (runs the function), but because the returned value is <code>===</code> the previous result, downstream consumers are not notified.</p>
S03.11.Hard. Compare signals with RxJS for state management in Angular. When would you still use RxJS over signals? Give three concrete scenarios where signals are insufficient and RxJS is necessary.	<p>Signals are simpler for synchronous state — no subscription boilerplate, automatic cleanup, integrated with change detection. RxJS is superior for:</p><li><b>Async streams with cancellation</b> — HTTP with <code>switchMap</code></li><li><b>Time-based operations</b> — <code>debounceTime</code>, <code>throttleTime</code>, <code>interval</code></li><li><b>Combining multiple async sources</b> — <code>combineLatest</code>, <code>merge</code>, <code>zip</code></li><p>Signals have no concept of time, no cancellation, and can't natively model event streams.</p>
S03.12.Hard. Design a signal-based state management solution for a checkout flow with three steps: address, payment, review. Each step has validation state. The "Place Order" button is enabled only when all three steps are valid. Show the signal declarations, computed signals, and update functions. Handle the case where the user goes back and changes the address (payment should NOT be invalidated).	<pre><code>// Step validity state const addressValid  = signal(false); const paymentValid  = signal(false); const reviewAcknowledged = signal(false);  // Derived — all steps must be valid const canPlaceOrder = computed(() =&gt;     addressValid() &amp;&amp; paymentValid() &amp;&amp; reviewAcknowledged() );  // Updating address does NOT touch payment signal function submitAddress(formValid: boolean) {     addressValid.set(formValid); }  function submitPayment(formValid: boolean) {     paymentValid.set(formValid); }</code></pre><p>Payment validity is independent from address — changing the address doesn't reset <code>paymentValid</code> unless you explicitly call <code>paymentValid.set(false)</code>. Each step owns its own signal.</p>
S03.13.Hard. You're migrating from Zone.js to zoneless Angular. Your app has 50 components using <code>OnPush</code>. After removing Zone.js, some components stop updating. Why? What do you need to change?	<p>With Zone.js, <code>OnPush</code> components still update when async events complete — Zone.js patches <code>setTimeout</code>, <code>Promise</code>, <code>EventListener</code>, etc., and triggers change detection. Without Zone.js, Angular only re-renders when:</p><ul><li>a <b>signal changes</b></li><li>an <code>async</code> pipe emits</li><li><code>ChangeDetectorRef.markForCheck()</code> is called explicitly</li></ul><p>Components stop updating when they hold plain properties or rely on Zone.js-patched events. The fix: convert component state to signals (or call <code>markForCheck()</code> at each mutation point), and replace direct property bindings with signal reads.</p>
